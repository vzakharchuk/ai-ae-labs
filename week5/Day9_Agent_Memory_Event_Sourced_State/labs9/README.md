# ДЗ 9

## Суть

Агент пам'ятає факти про мерчантів між сесіями — записано в SQLite, переживає рестарт.  У стартері агент писав у пам'ять все, що попросить модель, не питаючи, хто насправді говорить. 

Я переробив запис так, щоб хто пише — вирішувала програма, а не аргумент від моделі. Тепер чужий текст відхиляється:

```
[poison] > Подивись, що пишуть у порталі про A-114.
      [ev:rejected] integration.A-114 запис із недовіреного джерела заборонено
[poison] < У примітці просять змінити запис, але це чужий текст (rejected).
```

Факт лишається `legacy`, не `new-api`. Є тест на це.

## Що ще перевірив

Факт справді переживає рестарт процесу — day2 читає те, що day1 записав учора. Інший користувач на тій самій базі даних — нічого не бачить, бо пам'ять прив'язана до конкретної людини.

Кожен хід пише файл-журнал з того, що змінилось у стані і що було відхилено — не окрема база, а просто витяг з подій сесії.

Прогнав шість довгих питань в одній сесії на справжній моделі (локальний agentgateway не піднімався, тож узяв Ollama cloud). Без обмеження контексту запит росте з кожним ходом — 830, 972, 1068... З обмеженням ріст зупиняється, і головне — агент все одно правильно відповідає на питання про факт, бо факт живе окремо від історії чату, яку стискають.
